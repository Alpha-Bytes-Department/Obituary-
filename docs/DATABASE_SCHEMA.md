# Precise MongoDB Schema Design

This document details the exact Mongoose schema structures, types, validations, and default values for the platform's database collections.

## 1. `users` Collection
Stores all authentication, profile, and token request data.

| Field | Type | Required | Default / Notes |
|-------|------|----------|-----------------|
| `_id` | ObjectId | Yes | Auto-generated |
| `firstName` | String | Yes | Trimmed |
| `lastName` | String | Yes | Trimmed |
| `email` | String | Yes | Unique, lowercase, regex validated |
| `passwordHash`| String | Yes | Bcrypt hash (exclude from standard queries) |
| `refreshToken`| String | No | Stores the JWT refresh token for session management |
| `role` | String | Yes | Enum: `['user', 'admin']`, Default: `'user'` |
| `profileImage`| String | No | URL to Cloudinary/S3 asset |
| `tokenStatus` | String | Yes | Enum: `['none', 'pending', 'approved', 'rejected']`, Default: `'none'` |
| `createdAt` | Date | Yes | Auto-managed by Mongoose timestamps |
| `updatedAt` | Date | Yes | Auto-managed by Mongoose timestamps |

## 2. `obituaries` Collection
Stores all data related to the deceased, including media, family tree, and payment status.

| Field | Type | Required | Default / Notes |
|-------|------|----------|-----------------|
| `_id` | ObjectId | Yes | Auto-generated |
| `creatorId` | ObjectId | Yes | Ref to `User` |
| `deceasedFirstName`| String | Yes | Indexed for search |
| `deceasedLastName` | String | Yes | Indexed for search |
| `dateOfBirth` | Date | Yes | |
| `dateOfDeath` | Date | Yes | Used for "On This Day" feature |
| `age` | Number | Yes | Calculated before save |
| `location` | Object | Yes | `{ country: String, state: String, city: String }` (Indexed for search) |
| `images` | Array | Yes | Array of Objects: `[{ url: String, altText: String }]` |
| `biography` | String | Yes | Main memorial text |
| `familyTree` | Array | No | Array of Objects: `[{ name: String, relation: String, isLiving: Boolean, imageUrl: String }]` |
| `status` | String | Yes | Enum: `['pending_payment', 'live', 'archived']`, Default: `'pending_payment'` |
| `paymentMethod`| String | Yes | Enum: `['stripe', 'token', 'admin_override']` |
| `paymentId` | String | No | Stripe Intent ID or Ref to `PromoToken.code` |
| `isFeatured` | Boolean | Yes | Default: `false` (Managed by Admin) |
| `viewCount` | Number | Yes | Default: `0` |
| `createdAt` | Date | Yes | Auto-managed |
| `updatedAt` | Date | Yes | Auto-managed |

## 3. `condolences` Collection
Stores messages left by users or guests on specific obituaries, including virtual candles.

| Field | Type | Required | Default / Notes |
|-------|------|----------|-----------------|
| `_id` | ObjectId | Yes | Auto-generated |
| `obituaryId` | ObjectId | Yes | Ref to `Obituary` (Indexed) |
| `userId` | ObjectId | No | Ref to `User`. Null if posted by a guest. |
| `guestName` | String | No | Required if `userId` is null |
| `guestEmail` | String | No | Hidden from public view, used for moderation |
| `type` | String | Yes | Enum: `['normal', 'candle']`, Default: `'normal'` |
| `message` | String | No | Max length: 1000 characters. Optional if `type` is 'candle'. |
| `status` | String | Yes | Enum: `['live', 'hidden']`, Default: `'live'` (For admin moderation) |
| `createdAt` | Date | Yes | Auto-managed |
| `updatedAt` | Date | Yes | Auto-managed |


## 4. `promo_tokens` Collection
Stores codes generated by admins for users who requested free obituary postings.

| Field | Type | Required | Default / Notes |
|-------|------|----------|-----------------|
| `_id` | ObjectId | Yes | Auto-generated |
| `code` | String | Yes | Unique, alphanumeric (e.g., `MEM-A7X9-B2`) |
| `generatedBy` | ObjectId | Yes | Ref to Admin `User` who created it |
| `assignedTo` | ObjectId | Yes | Ref to `User` who requested the token |
| `isUsed` | Boolean | Yes | Default: `false` |
| `usedOnObituary`| ObjectId | No | Ref to `Obituary` once the token is redeemed |
| `expiresAt` | Date | Yes | e.g., 30 days from creation |
| `createdAt` | Date | Yes | Auto-managed |
